# AirVeil 0.12.0 beta 1

Fixes repeated camera alignment checks during idle audio or device handoffs, and adds a first-launch Settings walkthrough.

## Changes

- Core Motion disconnection no longer counts as AirPod removal. Automatic display management requires stable in-ear loss evidence.
- Interrupted camera checks stop instead of restarting on every sensor interruption. Use **Refresh direction** or **Enable blur** to retry; confirmed AirPod return permits one recovery check.
- Confirmed removal evidence arriving after a transport disconnect still receives the full debounce delay.
- New 14-step Settings tour with animated welcome, spotlight cutouts, automatic scrolling, Back/Skip, and replay through **Take a tour**. Supports light/dark appearance and Reduce Motion.
- First-launch sensor startup waits until the tour is completed or dismissed. Pending brightness restoration runs immediately.

## Install

Download **AirVeil-0.12.0-apple-silicon.dmg**, quit the previous app normally, and drag **AirVeil.app** into **Applications**. Open AirVeil to begin the tour.

Requires Apple silicon, macOS 14 or later, and compatible head-tracking AirPods. This remains a development-signed, non-notarized prerelease. macOS may block first launch on another Mac. Downloads require repository access while the repository is private.

## Validation and remaining limits

The full regression suite passed, including motion, wear evidence, camera/presence lifecycle, brightness restoration, input geometry, and GPU rendering. Tour navigation and persistence tests passed; all 14 steps were traversed in the live app, with 56 native layout renders across two sizes and both appearances.

The DMG was checksum-verified and mounted read-only. Its signed executable matches the installed 0.12.0 build 16. It contains only the app, Applications shortcut, and installation notes.

Physical AirPods/music-pause/phone-handoff acceptance remains pending. When macOS provides no usable in-ear status, automatic removal waits rather than guessing. Removal can be missed if the headset disconnects before reporting its ear-state change. Tracking interruptions clear blur and require a valid direction check before resuming. Private macOS compatibility interfaces remain subject to OS support.
